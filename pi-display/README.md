# MUNify CHASE — Pi display appliance

A headless Raspberry Pi 4 that boots straight into a full-screen, read-only
committee grid for the conference/committee it is assigned to. No keyboard,
no mouse, no per-device configuration in the image.

## How it works

1. **First boot** — the `chase-kiosk-auth` service runs the OAuth 2.0
   Device Authorization Grant. Chromium shows **QR #1** (the Logto
   verification URL). An organizer scans it and signs in as the shared
   CHASE display account.
2. The helper stores the refresh token + a Pi-generated device id under
   `/var/lib/chase-kiosk` (root-only), exchanges tokens for a CHASE
   session, and Chromium moves to `/kiosk`.
3. `/kiosk` shows **QR #2** (pairing) until an organizer assigns the
   device under **`/app/displays`** in CHASE (conference + optional
   committee). Then it renders the live grid.
4. Re-assignment and revocation propagate live (GraphQL liveQuery); no
   reboot. Subsequent boots skip QR #1 (stored refresh token).

The Pi never receives the refresh token back from CHASE — Logto rotates
refresh tokens on use, so the helper stays the sole owner and re-seeds the
browser session (via a top-level form POST to `/api/kiosk/session`) before
the access token expires.

## Logto / OIDC prerequisites

- Enable the **Device flow** for the shared display application.
- The display account's tokens must carry the `roles` claim including
  **`service_user`** (CHASE's `OIDC_ROLE_CLAIM=roles`). Per-device scoping
  is enforced by the `displayDevice` row, not the shared identity.
- Recommended: a **long access-token TTL** (hours). The kiosk briefly
  reloads when it re-seeds the session each token period; a long TTL makes
  that rare.

## Build & flash

```bash
cd pi-display
./build-image.sh        # prompts WiFi + base URL + OIDC client
# flash result/sd-image/*.img.zst to the SD card
```

`local.nix` (WiFi PSK + URLs) is generated by the builder and is
**gitignored** — never commit it.

## Operating

- **Assign / rename / revoke**: CHASE → `/app/displays` (global admins see
  all devices; conference admins see their conference's plus any
  unassigned device, so a freshly-paired Pi can be claimed at the venue).
- **Revoke a lost/stolen Pi**: toggle _Revoke_ on its row. The device
  immediately falls back to the pairing screen and can read nothing.
- **Rotate the shared account**: if the display account is compromised,
  rotate its credentials in Logto; all Pis fall back to QR #1 on next
  refresh and must be re-signed-in once.

## Security note (physical access)

The refresh token and device id are stored unencrypted in
`/var/lib/chase-kiosk` (Pi 4 has no TPM/secure element). A stolen Pi
exposes the **shared display** refresh token only (read-only,
service-user scoped). Mitigations: per-device _Revoke_, and shared-account
rotation. Treat physical access to venue displays accordingly.
